# v0.6.0-beta: Integration, reporting, evaluation, and deployment

The first end-to-end release. One command now goes from raw exports to a prioritized report.

## Highlights

- `csg run --sample` or `csg run --input <dir>` ingests, analyzes, prioritizes, and writes a report in one step.
- `csg report` re-renders the stored backlog as HTML, Markdown, JSON, or SARIF 2.1.0 (validated against the
  official schema). The HTML report is one self-contained file with no scripts and no external requests.
- Evaluation against tfsec and Checkov on 34 labeled defects: CloudSpendGuard precision 1.000, recall 0.941;
  Checkov 1.000 and 1.000; tfsec 0.889 and 0.941. Checkov is the stronger detector; see `docs/evaluation.md`.
- 1,000,000 CUR line items analyzed in 7.1 s (was 41 s) after bypassing the database in `csg run`. Peak memory is
  about 1.8 GB per million rows, so NFR1 is only partly met.
- Multi-stage distroless Docker image, GHCR publishing on version tags, and a scheduled-scan CloudFormation
  template.

## Fixed

- IMDSv2 rule no longer flags instances whose metadata endpoint is disabled (found by the evaluation).
- `csg run --input` skips JSON files that are not CloudTrail logs instead of failing.

## Known limits

- Terraform variables and data sources are not resolved (2 missed defects in the evaluation).
- Memory grows with the number of CUR rows; streaming aggregation is planned.
- No AWS Lambda deployment; see `docs/install.md` section 7.
- Human survey not yet collected.

## Install

```bash
git clone https://github.com/wisnuanggoro/cloudspendguard && cd cloudspendguard && git checkout v0.6.0-beta
make build && ./bin/csg run --sample --report out.html
```

Full details: `docs/install.md`, `docs/evaluation.md`, `CHANGELOG.md`.
